## 실제 변경 화면

시작 직업 선택, 캠프·휴식·지역 입장·체크포인트, 탐험·장면·지역 이벤트·NPC/동료 대화, 전투, 승리·전리품 및 비교, 상점, 제작/강화/조율, 직업 비전서/전직, 장비/가방/세트, 의뢰, 관계, 마지막 선택/후일담, 저장·불러오기 모달.

| 항목 | 적용 |
|---|---|
| 주요 행동 | 실제 높이 **52px**, 글자 **15px/600**, 반경 **10px**, 중앙 정렬 |
| 행동 그룹 | 2열이면 동일 폭·8px 가로 간격. 그리드 gap 8px. 단독/긴 이야기 선택은 전체 폭 |
| 설명 | 비용·확률·결과·전직 조건은 버튼 밖에서 전부 표시하고 `aria-describedby`로 연결. 핵심 선택을 말줄임표로 숨기지 않음 |
| 보조 조작 | 저장·닫기·페이지·직접 입력 실행은 44px 이상. 장비 슬롯은 이미지와 이름을 포함하는 별도 카드 규격 |
| 이미지/서술 | 상단 이미지와 하단 제목 → 실제 HP/MP/직업/골드 → 별도 서술 → 행동. 적 HP/다음 행동은 적 이미지 하단 |
| 보상 | 실제 아이콘/전용 이미지·희귀도 중심 카드, 기존 상승·하락 부호/화살표 유지 |
| 직업/장비 | 2:3 초상화와 기존 3슬롯 보존. 최초 직업 카드와 52px 선택 버튼 분리 |
| 색/토큰 | 검갈색 배경, 불씨 강조, 붉은 HP/푸른 MP. 의미 팔레트·버튼·간격·반경·기존 FX 시간 토큰 정리 |

CSS의 초기 light/dark fallback과 의도적인 반응형 레이어는 제거하지 않았다. 실제 기준 화면은 이미 다크 팔레트를 강제하고 있었고 테마 전환 기능이 없었다. OS light/dark 양쪽에서도 기존 다크 판타지 화면이 정상 표시되는지 검증했다.

## FX 및 로직 보호

기존 타격/플래시/데미지/치명타/회복/회피/상태/보상 등장/전설·신화/보스/히든/엔딩 FX를 그대로 사용한다. 새 효과나 새 진행 타이머는 추가하지 않았다. 기존 `.scene-hero`, `.scene-art`, `.enemy`, 첫 HP 자식, `.reward-summary`, `.fx-loot-card` 앵커를 유지했다. 렌더링 시 같은 `#bf-stats` 노드를 잠시 루트로 회수한 뒤 장면 안으로 이동하므로 중복 HUD나 유실이 없다.

좁아진 HP 앵커보다 피드백 텍스트가 길면 기존 화면 고정 rail을 사용한다. HP가 화면 안에 있을 때 붉은 피격 표시는 원래 HP 앵커에 남긴다. effect snapshot/descriptor/RNG와 .65초 정리 타이머는 그대로다. 기존 애니메이션 시간은 토큰으로 이름만 부여했다. reduced motion에서 흔들림·플래시·이동은 여전히 제거된다.

`test-ui-b-invariants.cjs`는 기준 main과 **174개 엔진·CSV·이미지 파일**의 SHA-256 일치, 114직업/1000장비, 전체 클릭 명령 블록 및 FX descriptor의 바이트 일치를 검사한다. 저장·전투 공식·이벤트·스토리·P1/P2/P3·RNG·보상 지급 시점은 변경하지 않았다.

## 남은 디자인 차이 및 검토 사항

- 시안 이미지가 placeholder이므로 실제 게임 이미지/정보에 맞춘 구현이다. Claude 원본 HTML의 픽셀 일치는 검증할 수 없다.
- 시안의 가로 장면 280–330px 예시 대신 일반 전투 이미지 320px, 이야기/직업 초상화는 기존 전체 2:3 그림을 보존한다. 긴 이야기는 자연스럽게 페이지 스크롤하며 선택 버튼까지 접근한다.
- 실제 스킬은 1개, 경로는 실제 12노드, 장비는 실제 3슬롯이다. 가짜 4스킬·5경로·샘플 HP/능력치/장비는 추가하지 않는다.
- 버튼 아래 설명도 보존하므로 세로 버튼 간 거리는 설명 길이를 포함한다. 버튼 자체는 모두 52px이고 행동 그룹의 gap은 8px이다.
- 실제 기기, 장시간 플레이, 발열·배터리·FPS, 사용자 체감/문체 평가는 미검증이다. 새 이미지 제작은 하지 않았다. 기존 미제작 이미지 목록은 P2/P3 이미지 문서대로 유지된다.
- 대규모 레이아웃 병합은 사용자 요청 §9에 따라 전후 이미지와 PR 검토 후 확인이 필요하다. 확인 전 main/Pages에 B안을 반영하지 않는다.

## CI에서 발견한 회귀와 최소 수정

첫 CI의 기존 기본 8폭 UI 검증에서 1280px 이야기 프레임이 `aspect-ratio`와 최대 높이 640px의 조합으로 폭까지 좁아졌다. `scene-visual`에 `width:100%`를 명시해 전체 가용 폭을 유지했다. 1280px에서 hero 764px / 이미지 762px / 높이 640px로 재현 검사를 통과했다. 그림은 계속 contain으로 보존한다.

P2 검증은 기존에 버튼의 `textContent` 안에 MP 비용이 있다고 가정했다. B안에서는 비용을 숨기지 않고 버튼 밖의 `aria-describedby` 설명으로 옮겼으므로, 검사도 연결된 설명이 실제로 보이며 MP 4를 표시하는지 확인하게 갱신했다. 검사 삭제/우회 없이 기존 선택→전투→장비→저장→후속 반응의 정확한 상태 대조를 유지한다. 실패 지점을 실제 Chromium에서 재현한 뒤 MP 4 선택의 비용 표시와 저장/RNG/결과 일치를 확인했다.

첫 CI의 B안/P3/FX 브라우저 job은 Chromium·WebKit·Firefox 모두 통과했다. 전체 CI는 위 두 회귀를 수정한 PR 최신 SHA에서 다시 실행하며, 최종 상태는 PR의 Checks를 기준으로 판단한다. 실패한 초기 실행을 최종 통과 결과로 취급하지 않는다.

## 재현

기존 환경에서 `npm ci --ignore-scripts`, `python3 build.py`, `node export-data.cjs`, `python3 export-site.py`, `python3 verify-html.py`. 내부 HTTP 서버의 URL을 `BF_QA_URL`로 지정하고 `node test-ui-b-invariants.cjs`, `node test-ui-b.cjs`, `node test-fx-ui.cjs`, 기존 UI/P3 검사를 실행한다. Chromium 실행 경로가 별도인 환경은 기존 `BF_CHROMIUM` 바인딩을 사용한다. Firefox는 이 클라우드의 사용자 namespace 제한 때문에 로컬 실행을 주장하지 않으며 일반 CI runner에서 실제 실행한다. 인증·TLS·브라우저 sandbox 설정을 바꾸지 않는다.
