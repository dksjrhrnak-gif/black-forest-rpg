# B안 UI 대조 — UI-1

기준 main: `419c70316307a5c26108b39f740276ede8fd5b0e`. 작업 브랜치: `qa/ui-b-mobile-pass`.

환경은 기존 onboarding setup을 재사용한다. Node/Playwright/빌드와 HTTP 브라우저 검증이 이미 준비되어 있으며 별도 의존성·저장 형식 변경은 필요 없다.

## 확인한 디자인

Claude URL은 HTTP 403으로 접근할 수 없었다. 사용자가 첨부한 ZIP의 탐험, 전투, 치명타, 직업·전직, 보상, 장비, 디자인 시스템·버튼 규격 PNG 7장을 직접 확인했다. PNG의 제안·예시 문구는 게임 명세로 취급하지 않는다.

## CSS 및 DOM 조사

`style.css`는 초기 light-dark 토큰, 명시적 light/dark fallback, 이후 다크 판타지/모바일/모달/장비/초상화/FX 레이어가 순차적으로 적용된다. 단순 중복 제거로 의도적인 media override를 삭제하지 않는다. 기존 화면은 최종 레이어가 다크 팔레트를 사용한다. B안의 검갈색·불씨 강조를 의미 토큰으로 정리하고 OS light/dark 환경 모두 검증한다.

주요 버튼은 `b()`의 게임 명령과 `menu()`의 게임 화면 이동에 분포한다. 과거 44px 최소 높이, 전투 52px 최소 높이, 장비 특수 스타일, 2열/1열 모바일 재정의 때문에 실제 높이와 폭이 달랐다. 버튼 내 긴 비용/결과 문장이 높이를 늘린다. 고정 52px을 적용하려면 행동과 설명을 분리해야 한다.

보조 저장·닫기·검색/페이지 이동은 별도 44px 규격, 장비 슬롯 선택은 이미지와 현재 장비 정보를 포함하는 독립 카드 규격으로 유지한다. 실제 게임 행동은 강화/제작/장착/판매/전직/이야기/전투/탐험을 포함해 52px로 통일한다.

FX 컨트롤러는 `.scene-hero`, 내부 `.scene-art`, `.enemy`, 첫 HP 박스, `.reward-summary`, `.fx-loot-card`, `.main`과 패널을 참조한다. 앵커를 유지하며 기존 CSS animation 및 reduced-motion만 재사용한다. 클릭 처리, RNG, 엔진 메서드 호출 순서 및 저장은 수정하지 않는다.

## 비교 증거

`test-ui-b.cjs`는 동일 저장·카메라·360/390/430px에서 전후 JPEG와 실제 버튼 측정을 남긴다. 초기 측정은 규격 적용 이전 기준이며 52px 통과 주장에 사용하지 않는다. 추가 회귀는 기존 FX 및 P1/P2/P3 브라우저 경로를 활용한다. 실제 기기·장시간 플레이는 별도 검토가 필요하다.
